# Локальный прототип кнопки «Играть»

Состояние: **не опубликован и не зарегистрирован как протокол Windows**. Публичный сайт продолжает предлагать архив v7. Прототип лежит в `client-pack/Invoke-LocalPlay.ps1` и принимает только `posle://play` и его нормальную форму `posle://play/`; ссылку браузера с ним пока не показываем.

## Что подтверждено первичными источниками

- [TLauncher Settings](https://tlauncher.org/en/settings.html) документирует ручную папку игры, список версий и аргументы **игры** (в том числе `--server`). API или CLI выбора версии и автоматического нажатия Play там нет.
- [TLauncher manual version installation](https://tlauncher.org/en/install-experimental-snapshot.html) подтверждает обнаружение JSON в `versions/<id>/<id>.json` и последующий ручной выбор версии.
- [Prism Launcher CLI](https://www.prismlauncher.org/wiki/getting-started/command-line-interface/) документирует `--launch <instance> --server <address>`. Это другая программа с отдельным экземпляром и учётной записью; замена TLauncher не выполнялась.
- [Microsoft URI activation](https://learn.microsoft.com/en-us/windows/apps/develop/launch/handle-uri-activation-dotnet) описывает регистрацию локального приложения для URI. Без этой регистрации обычная веб-страница не может запускать helper или установленный Minecraft.

## Проверяемое поведение прототипа

`Invoke-LocalPlay.ps1` только читает текущие файлы. Он принимает ровно два URI без query, fragment, дополнительного пути или порта; проверяет идентичность и версию журнала установки, хеши всех закреплённых клиентских файлов, профиль Forge, выбранные TLauncher папку/версию и цифровую подпись установленного TLauncher.exe. Поиск TLauncher повторяет три пути установщика; подстановка списка путей в тесте всё равно требует подписи TLauncher Inc. Параметр `-DryRun` не запускает программу и ничего не регистрирует. Обычный запуск открывает только подписанный TLauncher; игрок всё ещё нажимает Play в его окне. Существующее `servers.dat` позволяет выбрать сервер в меню; автоматический вход в мир через TLauncher не доказан.

Проверка без изменений в системе:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\client-pack\Invoke-LocalPlay.ps1 -DryRun
```

## Что нужно перед публичной интеграцией

1. Проверить повторно текущую сборку в **реальном TLauncher владельца** после его входа в аккаунт: видимость Forge, запуск, шейдер, сетевое подключение.
2. Спроектировать и испытать локальное приложение обработчика URI, которое получает только фиксированное действие, безопасно разбирает аргументы и регистрируется пользователем при установке. Затем проверить запрос разрешения браузера, отсутствие повторных запусков и восстановление после удаления.
3. Если обязателен автоматический запуск версии и вход на сервер без второго клика, выбрать и испытать launcher с официальным интерфейсом (`Prism Launcher` документирует такой API) **после отдельного решения владельца** об учётной записи и миграции сборки. TLauncher не следует автоматизировать недокументированными флагами или правками его аккаунта.

Нельзя считать текущий helper завершённым сценарием «один клик → игра»: регистрация протокола, настоящий браузерный вызов, нажатие Play, авторизация и подключение ещё не испытаны.

- На действующем выделенном клиенте владельца `-DryRun` завершился с кодом 0: сверены 27/27 закреплённых файлов, Forge 47.4.10, выбранные папка и версия TLauncher, а также подпись установленного `TLauncher.exe`. Программа не запускалась.
- `posle://play?cmd=calc` отклонён до обращения к файлам (код 1).
- Подставленная отдельная настройка TLauncher с выбранным Forge 47.4.20 отклонена (код 1); исходный файл настроек не менялся.
- При подстановке неподписанного текстового файла вместо TLauncher.exe запуск отклонён (код 1).
- Общая базовая Python-проверка ветки до добавления helper: 21/22 теста прошли, существующий `test_reference_catalog` упал на несовпадении размера 5283 и 5228 байт. Этот дефект не относится к helper.

После независимого замечания принят URI с завершающим `/`, а поиск подписанного TLauncher расширен до всех трёх путей установщика. `tests/test_local_play_host.ps1` прошёл в Windows PowerShell 5: две допустимые формы URI, выбор второго и третьего кандидата после отсутствующих файлов, пропуск неподписанного кандидата, шесть отказов для query, fragment, дополнительного пути, экранированного пути, другого хоста и порта. Отдельный запуск с путями по умолчанию и `posle://play/` завершился кодом 0. Во всех проверках использовался `-DryRun`; приложение и игра не запускались.
