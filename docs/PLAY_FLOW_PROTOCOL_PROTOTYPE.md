# Локальный прототип кнопки «Играть»

Состояние: **не опубликован для игроков**. Обработчик `posle://play` зарегистрирован и испытан только для текущего Windows-пользователя владельца; текущий сайт и ZIP v8 всё ещё дают обычную установку и не содержат браузерной ссылки на обработчик. Прототип принимает только `posle://play` и его форму `posle://play/`.

В репозитории подготовлены исходник `client-pack/POSLEProtocolHost.cs` и отдельные `Register-PlayProtocol.ps1` / `Unregister-PlayProtocol.ps1`, а также `PlayProtocolShellNotify.ps1`. Их пока нет в ZIP v8. Регистрация ставит обработчик только в `%LOCALAPPDATA%` текущего пользователя и добавляет `HKCU\Software\Classes\posle`; существующую чужую или машинную ассоциацию она не перезаписывает. Обработчик принимает ровно два URI и передаёт в PowerShell только фиксированное действие `posle://play`, так что параметры из браузера не попадают в командную строку помощника. Исполняемый файл содержит SHA-256 локального скрипта запуска, его зависимости и манифеста и проверяет их и отсутствие ссылок перед запуском. Для дочернего Windows PowerShell он задаёт каталог встроенных модулей: иначе при наследовании пути модулей PowerShell 7 команда `Get-FileHash` не загружалась и проверка клиента завершалась ошибкой. Одновременно активные вызовы одной установки блокируются, а повтор в течение 60 секунд после успешного открытия подавляется. Имя блокировки содержит SID пользователя и хеш пути установки, чтобы разные установки не мешали друг другу. Обновление допускается только если прежние файлы совпадают со своим журналом, и сохраняет старую папку как backup. При чужих или изменённых файлах обновление останавливается. Прерванную собственную запись ассоциации можно завершить повторным запуском регистрации; исполняемая команда записывается последней. Удаление проверяет собственный маркер, путь, команду и структуру ключа; оно оставляет клиентские файлы, обработчик и сохранения. Реальный вызов через браузер пока **не проверен**.

## Что подтверждено первичными источниками

- [TLauncher Settings](https://tlauncher.org/en/settings.html) документирует ручную папку игры, список версий и аргументы **игры** (в том числе `--server`). API или CLI выбора версии и автоматического нажатия Play там нет.
- [TLauncher manual version installation](https://tlauncher.org/en/install-experimental-snapshot.html) подтверждает обнаружение JSON в `versions/<id>/<id>.json` и последующий ручной выбор версии.
- [Prism Launcher CLI](https://www.prismlauncher.org/wiki/getting-started/command-line-interface/) документирует `--launch <instance> --server <address>`. Это другая программа с отдельным экземпляром и учётной записью; замена TLauncher не выполнялась.
- [Microsoft URI activation](https://learn.microsoft.com/en-us/windows/apps/develop/launch/handle-uri-activation-dotnet) описывает регистрацию локального приложения для URI. Без этой регистрации обычная веб-страница не может запускать helper или установленный Minecraft.
- [Microsoft SHChangeNotify](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify) требует уведомлять Shell об изменениях ассоциаций, включая зарегистрированные протоколы. Подготовленные скрипты делают это после успешной записи или удаления ключа; реальное обновление кэша ещё не проверено.

## Проверяемое поведение прототипа

`Invoke-LocalPlay.ps1` только читает текущие файлы. Он принимает ровно два URI без query, fragment, дополнительного пути или порта; проверяет идентичность и версию журнала установки, хеши всех закреплённых клиентских файлов, профиль Forge, выбранные TLauncher папку/версию и цифровую подпись установленного TLauncher.exe. Поиск TLauncher повторяет три пути установщика; подстановка списка путей в тесте всё равно требует подписи TLauncher Inc. Параметр `-DryRun` не запускает программу и ничего не регистрирует. Обычный запуск открывает только подписанный TLauncher; игрок всё ещё нажимает Play в его окне. Существующее `servers.dat` позволяет выбрать сервер в меню; автоматический вход в мир через TLauncher не доказан.

Проверка без изменений в системе:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\client-pack\Invoke-LocalPlay.ps1 -DryRun
```

## Что нужно перед публичной интеграцией

1. Проверить повторно текущую сборку в **реальном TLauncher владельца** после его входа в аккаунт: видимость Forge, запуск, шейдер, сетевое подключение.
2. Проверить подготовленный обработчик на отдельной Windows-учётной записи или изолированном ПК: установку из будущего ZIP, запрос разрешения браузера, вызов из браузера и восстановление после удаления. Локальная регистрация, вызов через Windows Shell, подавление повтора и цикл удаления/повторной регистрации уже испытаны на текущем пользователе. ZIP v8 не содержит эти файлы.
3. Если обязателен автоматический запуск версии и вход на сервер без второго клика, выбрать и испытать launcher с официальным интерфейсом (`Prism Launcher` документирует такой API) **после отдельного решения владельца** об учётной записи и миграции сборки. TLauncher не следует автоматизировать недокументированными флагами или правками его аккаунта.

Нельзя считать текущий helper завершённым сценарием «один клик → игра»: настоящий браузерный вызов, автоматическое нажатие Play, авторизация и подключение ещё не испытаны. TLauncher не предоставляет проверенный CLI для выбора версии и входа на сервер; после открытия лаунчера игрок нажимает Play сам.

## Локальные результаты 11.10.2026

- Исправленный ZIP v8 проверен по точному составу архива и SHA-256. Из него выполнена обычная установка в ранее отсутствовавшую папку: код 0, Forge 47.4.10 и Java 17 установлены, 27/27 файлов совпали с манифестом. Параметры выбрали DMS, Fresh Animations и Tissou's Zombie Pack. Это проверка **установщика**, а не URI-протокола, запуска TLauncher или подключения.
- На действующем выделенном клиенте владельца `-DryRun` завершился с кодом 0: сверены 27/27 закреплённых файлов, Forge 47.4.10, выбранные папка и версия TLauncher, а также подпись установленного `TLauncher.exe`. Программа не запускалась.
- `posle://play?cmd=calc` отклонён до обращения к файлам (код 1).
- Подставленная отдельная настройка TLauncher с выбранным Forge 47.4.20 отклонена (код 1); исходный файл настроек не менялся.
- При подстановке неподписанного текстового файла вместо TLauncher.exe запуск отклонён (код 1).
- В первоначальной изолированной ветке со старым географическим манифестом один из 22 Python-тестов не прошёл из-за размера 5283 против 5228 байт. После переноса прототипа в актуальную ветку все **22/22** Python-тестов прошли; это отдельно от проверки реального запуска TLauncher.

После независимого замечания принят URI с завершающим `/`, а поиск подписанного TLauncher расширен до всех трёх путей установщика. `tests/test_local_play_host.ps1` прошёл в Windows PowerShell 5: две допустимые формы URI, выбор второго и третьего кандидата после отсутствующих файлов, пропуск неподписанного кандидата, шесть отказов для query, fragment, дополнительного пути, экранированного пути, другого хоста и порта. Отдельный запуск с путями по умолчанию и `posle://play/` завершился кодом 0. Во всех проверках использовался `-DryRun`; приложение и игра не запускались.

`tests/test_play_protocol_host.ps1` компилирует C#-обработчик в удаляемой временной папке. Он отклоняет четыре опасных URI и дополнительные аргументы, две допустимые формы направляет в подставной безвредный скрипт как фиксированное `posle://play`, подавляет немедленный повтор и отвергает изменённые после компиляции скрипт, зависимость и манифест. Он также проверяет два одновременных вызова одной установки, параллельные вызовы двух независимых установок и запуск через `ProcessStartInfo` с путём модулей PowerShell 7. `tests/test_play_protocol_registration_plan.ps1` сверяет планы регистрации и удаления, проверяет отказ пути за пределами `%LOCALAPPDATA%`, `-WhatIf` без записи, компиляцию Shell-уведомления без его отправки, подготовку исполняемого файла во временной папке, отклонение `DelegateExecute` и чужого подключа, порядок частичной записи через подставной ключ, сохранение старой сборки при обновлении и отказ для изменённых или посторонних файлов. Оба теста прошли при одновременном запуске. Сами изолированные тесты не меняли реальный ключ `posle` и клиентские файлы владельца; отдельно проведена системная проверка ниже.

После тестов выполнена контролируемая проверка на текущем пользователе. Перед регистрацией ключа `HKCU\Software\Classes\posle` не было, а `Invoke-LocalPlay.ps1 -DryRun` проверил Forge 47.4.10, 27 файлов, выбранные в TLauncher папку/версию и подпись `TLauncher Inc.`. Первая регистрация выявила проблему загрузки `Get-FileHash` в дочернем Windows PowerShell при наследовании пути модулей PowerShell 7. Тест на прямом запуске собранного host через `ProcessStartInfo` воспроизвёл отказ; после настройки встроенных модулей он прошёл. Из-за UTF-8 без BOM кириллическое имя приложения в первом ключе отобразилось неверно, поэтому его заменили на ASCII `POSLE Minecraft Play` и повторно зарегистрировали обработчик.

`Start-Process 'posle://play'` через Windows Shell создал `last-success-utc.txt`, открыл подписанный `TLauncher.exe` и окно `TLauncher 2.9378`; игровой клиент автоматически не запускался. Повторный вызов не изменил состояние, а `posle://play?cmd=calc` не открыл нового процесса. Изменённое тестом имя приложения привело к отказу `Unregister-PlayProtocol.ps1` (код 1, ключ сохранён); прежнее имя восстановили. Обычное удаление прошло с кодом 0, ключ исчез; повторная регистрация прошла с кодом 0, ключ создан снова. Зарегистрированный собственный ключ сейчас оставлен на ПК владельца. Новые окна TLauncher, открытые тестами, закрыты; прежний процесс лаунчера сохранён. Ни тест, ни сайт не нажимали Play в TLauncher и не проверяли вход в игру через браузер.
